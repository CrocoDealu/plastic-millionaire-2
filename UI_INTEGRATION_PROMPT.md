# Prompt: Integrate the Pixel UI & HUD Pack into This Godot Game

You are working directly inside this Godot repository. Your task is to redesign the existing game UI using the pixel-art UI sprites in:

```text
~/Documents/assets/Pixel UI & Hud
```

The game is **Plastic millionaire second try**, a 2D recycling/incremental game. Make the UI look cohesive, polished, readable, and intentionally pixel-art rather than merely placing random decorative sprites around the existing controls.

## First: inspect before editing

Read the existing project and understand the current behavior before changing anything:

- `project.godot`
- `main.tscn`
- `main.gd`
- `recycler_game.gd`
- `resource_inventory.gd`
- `generator_model.gd`
- `bag_system.gd`
- `drop_box.gd`

The main scene currently contains:

- A top inventory row with `Plastic`, `Flakes`, `Pellets`, `Fabric`, and `Money`.
- A central clickable bag with `BagButton` and `BagTexture`.
- A left-side action/message area with `SellMaterials`.
- A right-side `TabContainer` with `Workshop` and `Shop`.
- Three workshop generator cards: sorter, pelletizer, and loom.
- Generator progress bars and controls for Buy, Run, Collect, Speed, Yield, Auto-In, and Auto-Out.
- Shop upgrade buttons.
- A bottom achievements title and five achievement labels.
- Falling collectible boxes and existing click/burst effects that must continue to work.

Do not replace or weaken the game logic. Keep the existing unique node names, signal connections, game state updates, bag interaction, drag collection, automatic collection, generator behavior, shop behavior, and achievement updates working.

Copy only the selected source images into a repository path such as `assets/ui/` and reference them through `res://...`. Never leave the project dependent on an absolute path under `~/Documents`.

## Visual direction

Create a restrained pixel-art industrial recycling interface:

- Use a dark blue/charcoal base that complements the current background.
- Use blue/teal for neutral interactive UI.
- Use green for recycling/production success states.
- Use gold/yellow sparingly for money, valuable drops, and completed achievements.
- Reserve red for warnings or unavailable actions, not normal decoration.
- Keep the clickable bag as the visual focal point.
- Make the right-side workshop/shop area feel like a control console or factory dashboard.
- Make resource counts immediately scannable.
- Avoid visual noise, excessive animation, and mixing too many sprite families.
- Prefer one main panel family, one main button family, and a small accent palette.

## Implementation requirements

1. Use Godot-native UI nodes and layout containers:
   - `Control`, `PanelContainer`, `MarginContainer`, `VBoxContainer`, `HBoxContainer`, `GridContainer`, `ScrollContainer`, and `TabContainer`.
   - Preserve responsive anchors and container-based sizing.
   - Do not replace the current layout with fragile absolute-positioned UI.
2. Build reusable styling rather than duplicating ad-hoc properties:
   - Create a shared `Theme` resource and/or reusable UI component scenes where appropriate.
   - Use `StyleBoxTexture` for fixed panels/buttons when the sprite is a frame.
   - Use `NinePatchRect`/nine-patch-compatible styling for scalable panels and buttons.
   - Set patch margins from the actual source sprite borders so corners remain crisp.
   - Use `AtlasTexture` regions when a source sheet contains multiple UI elements.
3. Implement button states correctly:
   - Normal/unpressed.
   - Hover/highlighted.
   - Pressed/press feedback.
   - Disabled/locked, using a readable visual treatment rather than making text disappear.
   - Do not break keyboard/controller focus or mouse/touch input.
4. Keep all existing button text and dynamic text updates unless a small wording/layout change is necessary for readability.
5. Preserve the existing `%UniqueName` lookups in `main.gd`, or update all dependent references safely if a node must be reorganized.
6. Do not put gameplay logic into UI drawing code. UI should remain a presentation layer driven by the existing game signals and refresh methods.
7. Keep tooltips functional for generator upgrades and shop upgrades. If custom tooltip panels are needed, make them readable at all window sizes.
8. Keep the central bag clickable and visually responsive. Existing click/burst effects must remain visible above or beside the UI as appropriate.
9. Ensure dropped resource boxes remain collectible and are not covered by an opaque UI control. Set appropriate `mouse_filter` values on decorative/background controls.
10. Do not add per-frame UI work unnecessarily. Avoid `_process()` changes unless they are required for a visible UI effect.

## Pixel-art rendering rules

- Preserve crisp pixels everywhere.
- Use nearest-neighbor texture filtering. The project already uses nearest filtering globally; do not introduce linear filtering for these sprites.
- Check every new `TextureRect`, `Sprite2D`, `StyleBoxTexture`, and `NinePatchRect` for inherited filtering and scaling behavior.
- Prefer integer or clean pixel-multiple scaling. Avoid fractional scaling that causes blurry edges.
- Preserve aspect ratios for icons and decorative sprites.
- Do not stretch small sprites non-uniformly.
- Keep text readable against the pixel-art frames. Use a suitable pixel font only if one already exists in the project; do not invent a dependency without checking the repository.

## Suggested UI mapping

Use your judgment, but start from this structure:

### Top resource HUD

- Put the five resource counters into a single framed inventory strip.
- Use `ValueSlots` or a compact panel for each counter.
- Give money a gold accent and the recycling materials a consistent cool/green palette.
- Keep the values prominent and ensure large numbers remain readable.

### Left action panel

- Style `SellMaterials` as the primary economy action.
- Place `Message` inside a framed status/message area.
- Make success, warning, and informational messages visually distinct without changing the game logic.

### Central bag area

- Keep the existing `BagButton` and `BagTexture` behavior.
- Add a subtle panel/banner or decorative frame only if it improves hierarchy.
- Do not cover the bag with a mouse-blocking decorative control.
- Keep click feedback and bag alpha/burst behavior intact.

### Workshop tab

- Turn each generator row into a clear reusable machine card using panel sprites.
- Use a banner or decorated title for the generator name.
- Make recipe, stored output, and production rate secondary but readable information.
- Skin each progress bar with `ValueBars`.
- Use a consistent button style, with Buy/Run/Collect visually prioritized over upgrade toggles.
- Clearly distinguish disabled, locked, purchased, and active automation states.
- Keep the workshop scrollable at smaller window sizes.

### Shop tab

- Make shop upgrades look like selectable upgrade cards or framed list entries.
- Keep the existing dynamic cost text and purchased state.
- Use tooltips for detailed descriptions rather than overcrowding each card.
- Use a selector or highlighted state to communicate hover/focus/purchase status.

### Achievements

- Put the achievements title in a banner.
- Display each achievement in a compact slot/card.
- Use a small star/jewel/decorator only if it improves readability.
- Make locked and unlocked states immediately distinguishable while retaining the existing checkmark/circle meaning.
